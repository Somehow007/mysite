> 范围：RAG 模块（知识库管理 + 智能问答聊天）、系统管理员各管理界面、个人主页/个人中心

## 一、现状诊断

### 1.1 已有基础（值得保留的资产）

- **主题系统完善**：7 套主题 + CSS 变量 token（`src/styles/tokens.css`、`themes/`），`data-theme` + `.dark` 双轨，玻璃拟态是全站视觉签名。
- **技术栈健康**：Vue 3 + Tailwind 4 + Pinia + lucide 图标，无重型 UI 库历史包袱。
- **RAG 后端链路完整**：建库 → 选文入库 → 异步分块 → Embedding → pgvector → 检索/Rerank → SSE 流式问答，前端 `useChat` 状态机（流式/失败/重试/取消）已具备。
- `DashboardView` 的智能分页、批量操作浮条、空状态设计已接近可组件化的成熟度；`UserManageView` 的确认弹窗模式接近通用 ConfirmDialog。

## 二、设计目标与原则

**三个可检验的目标：**

1. **体验**：任何操作 100ms 内有反馈，任何异步状态可见（加载/进行中/失败/空），任何危险操作有统一确认门槛，任何引用可溯源跳转。
2. **美学**：全站只存在一套语义 token，消灭硬编码色值；同类元素（表格/徽章/按钮/弹窗）在任何页面渲染结果一致；亮暗主题下对比度均达标（正文 ≥ 4.5:1）。
3. **稳定**：所有列表服务端分页；所有轮询有退避与上限；所有危险操作可确认、可回滚或软删除；组件层统一处理 loading/error/empty 三态，页面不再各自实现。

**原则：**

- **先系统后页面**：先沉淀 token 与组件库（第 3 周），再逐页迁移；不允许页面级一次性样式新增。
- **最小侵入**：保留现有路由结构、API 层（`src/api/*`）、`useChat` 状态机、主题机制；重构集中在视图层与组件层。
- **组件即规范**：统一从 `components/ui/` 导出，页面禁止手写表格/弹窗/分页；ESLint 规则（`no-restricted-syntax`）拦截 `alert`/`confirm` 调用。

## 三、设计系统层（所有页面的地基）

### 3.1 Token 治理

现状 token 已覆盖背景/文字/边框/玻璃，缺**语义状态色**。新增一组随主题切换的状态 token：

```css
:root {
  --success: #10B981; --success-subtle: rgb(16 185 129 / 0.12);
  --warning: #F59E0B; --warning-subtle: rgb(245 158 11 / 0.12);
  --danger:  #EF4444; --danger-subtle:  rgb(239 68 68 / 0.12);
  --info:    #3B82F6; --info-subtle:   rgb(59 130 246 / 0.12);
}
[data-theme$="-dark"] { /* 各色微调亮度，subtle 透明度升至 0.18 */ }
```

配套 Tailwind `@theme` 映射为 `text-success bg-success-subtle` 等工具类。**徽章/提示条/状态点只允许使用这 4 组 + accent + muted**，一次性全局替换硬编码色（A1），删除 `surface-primary` 残留 token（A2），清理无效类（A3）。

按钮体系补齐 `.btn-danger`（现状危险按钮是手写 `bg-red-500`）。

### 3.2 组件库 `src/components/ui/`

按缺口优先级建设，每个组件内置 loading/error/empty 三态与深色适配：

| 优先级 | 组件 | 来源/说明 |
|--------|------|-----------|
| P0 | `ConfirmDialog` | 以 `UserManageView` 的 title/message/action 模式为种子；支持 danger 类型、高危操作「输入名称确认」二级门槛；全局 `useConfirm()` 返回 Promise |
| P0 | `DataTable` | 统一三种表格形态；列配置 + 插槽；内置排序、选择、服务端分页接口、行展开；移动端自动降级为卡片列表 |
| P0 | `Pagination` | 以 `DashboardView` 智能页码折叠为准，统一全站 |
| P1 | `SearchFilterBar` | 收敛 5 处复制粘贴的「搜索 + 筛选 + 排序 + 升降序」筛选栏 |
| P1 | `Badge` / `StatusDot` | 仅允许语义色 |
| P1 | `EmptyState` / `ErrorState` | 图标 + 文案 + 动作按钮规范（ErrorState 必带重试） |
| P1 | `Modal` | 统一遮罩、ESC/点击关闭、焦点圈定、关闭按钮一律 lucide `X` |
| P2 | `Dropdown` | 用浮层库或 `@vueuse` 的 `onClickOutside` + 自动定位替换手写 `getBoundingClientRect`（R4） |
| P2 | `Drawer` | 移动端侧边栏抽屉、分块预览侧滑面板复用 |

数据获取模式抽为 `usePagedList(fetcher)` composable：统一 page/size/sort/keyword 状态、防抖搜索、请求竞态取消（AbortController）、错误重试——替换各页手写的 `loading` ref + try/catch（R1、E5、E6 一并解决）。

## 四、RAG 模块重构方案

效果图：`mockups/01-rag-knowledge.html`（知识库管理）、`mockups/02-rag-chat.html`（智能问答）

### 4.1 知识库管理（KnowledgeManageView）

**信息架构：从「一镜到底长页」改为「库列表 → 库详情」两级视图。**

现状选中知识库后详情面板接在卡片网格下方，页面极长。改为：

- **未选中态**：知识库卡片网格 + 每个卡片直接显示健康度摘要（就绪/处理中/失败三个状态点 + 数量），管理员不用点进去就能看到哪个库有问题。
- **选中态**：详情区替换网格区（或桌面宽屏下左侧 280px 库列表 + 右侧详情双栏），含面包屑「知识库 / 博客全站文章」，可快速切库。

**详情区结构：**

1. **统计条**：总数 / 就绪 / 处理中 / 失败 4 格，处理中带旋转指示与「每 5 秒自动刷新」提示。
2. **三个 Tab**：「已同步文档」「添加文章」「分块设置」。
3. **文档列表**：服务端分页（解决 R1），状态筛选胶囊组，行内操作：重试 / 预览 / 删除。
4. **分块预览**（新增，解决 E3）：文档行展开显示切片列表（chunk 序号、内容片段、字符数、token 估算）；需要后端补一个 `GET /knowledge/documents/{id}/chunks?page=` 只读接口（复用现有 chunk 表，改动小）。
5. **分块设置 Tab**（解决 E3 后半）：把弹窗里的「高级配置」升格为独立 Tab，暴露后端已支持的 `fixed_size / structure_aware` 模式选择；每个参数给单位、推荐值与一句人话说明（如「chunkSize：每个切片的最大字符数，推荐 512；过大会降低检索精度，过小会切断语义」）。
6. **文件上传入口**（补齐）：`KnowledgeDocument.sourceType` 已有 `UPLOAD` 类型，后端规划支持 Markdown 上传——UI 在「添加文章」旁提供「上传文档」按钮（拖拽区 + 格式/大小限制说明）。

**状态实时化（解决 E2，见 §7 健壮性）：**

- 选中库且存在 `PENDING/CHUNKING` 文档时启动轮询：5s 间隔、指数退避至 30s 封顶、页面隐藏（`document.visibilityState`）时暂停、全部就绪后停止。
- 列表行内状态变化用局部更新而非整表刷新，避免滚动位置跳动。

**反馈统一：** 删除文档/知识库一律走 `ConfirmDialog`（删除库属于高危，要求输入库名确认），结果一律 Toast，废弃原生 `confirm()`（E1）。

### 4.2 智能问答聊天（ChatWidget 族）

保留 `useChat` 状态机与玻璃拟态面板，做六点增强：

1. **来源可溯源（E4）**：`ChatSources` 的来源卡片渲染为 `<router-link>`（`sourceType=ARTICLE` 时用 `articleId` 跳文章页），带序号徽标 `[1]` 与正文角标联动 hover 高亮；上传类来源显示文档名不可跳。
2. **限流与断网差异化（R2）**：429 响应显示 warning 横幅「提问过于频繁，请 N 分钟后重试（每小时限 20 次）」并禁用输入框倒计时；SSE 断线区分「网络中断可重试」与「生成失败」，失败气泡保留已生成的部分内容 +「从断点重试」。
3. **会话管理（E10）**：历史会话支持重命名（双击标题行内编辑）与删除（ConfirmDialog）；切换会话时主消息区显示骨架屏（现状 loadingHistory 只作用于侧栏）。
4. **匿名与登录统一（E10）**：采纳后端 visitorId 设计——匿名用户可直接提问（消耗匿名额度），面板顶部提示「登录后可保存历史对话」引导登录，登录后后端合并 visitorId 历史；不再强制跳登录页。
5. **输入区状态可见**：显示剩余额度「剩余 15 次/小时」；发送中按钮变为停止键（已有）+ 输入框软禁用。
6. **推荐问题可配置**：硬编码的 3 个推荐问题改由知识库配置或站点设置下发，为空则不渲染该区。

## 五、管理后台重构方案

效果图：`mockups/03-admin-console.html`（以用户管理为完整示例）

### 5.1 布局与导航

- `DashboardLayout` 保留左栏 + 内容区骨架；**侧边栏移动端抽屉化**（`< 768px` 时隐藏，顶栏汉堡按钮触发 `Drawer`，遮罩点击关闭）（E8）。
- 侧边栏按信息架构分组而非平铺 10 项：**内容**（文章/分类/标签/合集/图片）、**社区**（用户/评论）、**系统**（知识库/设置），组间细分隔线与小号组标题，降低扫描成本。
- 修复 `DashboardSidebar.vue:61` 无效类；面包屑统一「控制台 / 用户管理」。

### 5.2 七页统一改造

所有管理页套用同一页面骨架：`PageHeader（标题+副标题+主操作）→ 可选统计卡 → SearchFilterBar → DataTable/卡片列表 → Pagination`，差异只留在列配置与行操作上：

| 页面 | 专属改造点 |
|------|-----------|
| 仪表盘/文章 | 保留现有体验（已最优），把其筛选栏/批量条/分页迁移为共享组件后回本页复用；scoped CSS 逐步收敛进组件 |
| 用户管理 | `alert()` 全部换 Toast；角色循环切换改为下拉（循环点击误操作率高）；删除用户为高危操作：输入用户名确认，文案说明文章归属影响 |
| 评论管理 | 全量页码平铺改智能分页；`confirm()` 换 ConfirmDialog；列表保留卡片形态但收敛进统一 `CommentItem` 组件；审核操作加 Toast + 乐观更新 |
| 分类管理 | 三层复制粘贴模板重写为**递归 `CategoryTreeNode` 组件**（支持任意层级，缩进用 CSS 变量按深度计算）；整页 alert/confirm 换 Toast + ConfirmDialog；顶部加搜索（按名称过滤树并高亮）；移动端树缩进减半 |
| 标签管理 | 已较完整，仅统一组件与反馈 |
| 合集管理 | 保留错误重试态（唯一有的）并推广为全站 ErrorState 规范 |
| 图片管理 | 补**上传入口**（拖拽上传 + 进度条）与批量选择删除；hover 才出现的操作按钮改为常显小图标（触屏可达）；图片卡加灯箱预览 |

### 5.3 统计卡片

用户/评论/文章页头加轻量统计行（总数/今日新增/异常项），数据复用现有分页接口的 total 字段 + 一个聚合接口（若后端暂缺，可后置，不阻塞主流程）。

## 六、个人主页与个人中心方案

效果图：`mockups/04-profile.html`

### 6.1 新增公开个人主页 `/user/:username`

现状用户身份无对外承载（E7）。新增公开主页，**访客视角**：

- **资料卡**：大头像、昵称 + @用户名、角色徽章、bio、加入时间/位置/外链、「关注」按钮（如暂不做关注功能则后置，先放「Ta 的合集」入口）。
- **统计行**：文章数 / 合集数 / 获赞 / 被收藏（公开数据聚合）。
- **Tab**：「文章」「合集」「关于」；「收藏」Tab 仅本人可见（带锁标识），访客视角不渲染。
- 文章列表复用首页 `ArticleList` 流式样式，保持全站内容浏览体验一致。
- 文章页作者名、评论头像处链接到该页，形成站内身份闭环。
- 后端需补：`GET /users/{username}/profile`（公开资料 + 统计）、`GET /users/{username}/articles`（已发布文章分页）。

### 6.2 个人中心整合（本人视角）

- **入口统一**：顶栏用户菜单收敛为「个人主页 / 我的收藏 / 个人设置 / 退出登录」；个人设置从 Dashboard 布局中独立（或在公开主页本人视角下提供「编辑资料」按钮直达），普通用户不必进入「控制台」语境。
- **设置页修复与增强**：
  - 修复手机号死字段（E9）：要么接通后端字段，要么移除输入框——二选一，不允许静默丢弃。
  - 邮箱显示「已验证/未验证」状态徽章；手机号显示「未绑定 + 去绑定」。
  - 提示条全面替换硬编码 `bg-green-50/text-red-500` 为语义 token（A1）。
  - 新增「账号安全」区：修改密码 + 登录设备列表（当前设备标识、远程下线）；无设备管理后端时可后置，先留 UI 规范。
  - 保存成功 Toast + 按钮短暂 success 态；表单脏检测，离开页面前未保存提示。

## 七、稳定性与健壮性设计（横切关注点）

1. **请求层**：`usePagedList` 统一 AbortController 竞态取消（切页/改筛选时取消在途请求）；搜索输入 300ms 防抖；所有列表服务端分页，单页 ≤ 50 条。
2. **轮询策略**：仅知识库详情需要；5s 起步、失败后 ×2 退避、30s 封顶、连续 5 次失败停止并提示手动刷新；标签页隐藏时 `pause`，恢复可见时立即补一次。
3. **SSE 健壮性**：`useChat` 增加断线分类（网络错误/服务端错误/限流）；限流读 `Retry-After` 头倒计时；重试复用同一 conversationId，不重复计入额度（需后端幂等配合）。
4. **危险操作门槛**分级：普通删除 → ConfirmDialog 一次确认；不可逆且影响面大（删库、删用户、批量删除 > 10 项）→ 输入名称确认；批量操作沿用 Dashboard 的乐观更新 + 失败回滚模式并推广。
5. **权限**：前端守卫仅作 UX 层，继续保留；在重构文档中明确标注「角色判断以服务端鉴权为准」，并顺手清理 DEVELOPER 旧角色兼容逻辑（后端已无此值时）。
6. **浮层定位**：`Dropdown`/菜单类统一基于锚点自动定位（视口边界翻转），替换手写 rect 计算（R4）。
7. **空数据与边界**：空态/错误态/加载态由组件强制（DataTable 无数据必须显示 EmptyState，错误必须显示 ErrorState + 重试）；分页边界（删除末页最后一条后回退页码）收进 `usePagedList`，不再各页手写 `total -= 1`。
